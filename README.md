# wrapfile

当前版本提供命令行版本查询与备份密钥生成。

## 构建与运行

```sh
cargo build --offline
./target/debug/wrapfile --version
```

输出：

```text
wrapfile 0.1.0
```

## 生成密钥文件

后续加密备份所需的密钥通过 `keygen` 子命令生成：

```sh
./target/debug/wrapfile keygen path/to/backup.key
```

成功时以状态码 0 结束，并在标准输出简短提示保存位置，例如：

```text
Key saved to path/to/backup.key
```

### 密钥文件格式

- 内容是**恰好 32 字节的原始二进制密钥**。
- 不含任何文本编码（如 hex/base64）、换行、文件头或其他附加字节。
- 密钥字节来自操作系统的密码学安全随机源（由成熟的 Rust 库
  [`getrandom`](https://crates.io/crates/getrandom) 提供，Linux 上为
  `getrandom(2)` / `/dev/urandom`），与时间、路径等无关，不可推算。
- 命令的标准输出与错误信息都不会包含或展示密钥字节。

### 文件权限

在 Unix 系统上，成功生成的密钥文件权限**恰为 `0600`（仅当前用户可读写，
组和其他用户无任何权限）**，与用户的默认 umask 无关：

- umask 宽松时，组和其他用户不会在创建时获得任何权限；
- umask 严格时（例如 `0777`，会使新文件暂时连所有者权限都被屏蔽），命令会在
  写入任何密钥字节之前将权限补全为 `0600`，不会接受 `0400`、`0200` 或 `0000`
  这类所有者不可读写的结果作为成功。

从文件创建开始，组和其他用户就始终没有读、写或执行权限——不会先创建一个更开放的
文件再在结束时收紧。如果底层文件系统拒绝设置 `0600`，或设置后无法确认权限确实
为 `0600`（例如某些不支持 Unix 权限的文件系统挂载），命令会报错并以状态码 1
失败：此时尚未写入密钥字节，本次生成的空文件会被删除，标准输出也不会出现成功
提示。命令不会通过修改父目录或其他已有文件的权限来达成结果。

### 拒绝覆盖与路径要求

生成操作只接受一个尚不存在的路径，以下情况都会**失败（状态码 1）**，且已有的
文件、目录或符号链接及其内容保持原样：

- 目标位置已存在任何文件、目录或符号链接（包括指向不存在位置的悬空符号链接；
  命令不会沿符号链接创建文件）；
- 目标的父目录不存在——命令**不会自动创建父目录**；
- 父目录不可写、随机源不可用、写入未完成或无法保证 `0600` 权限。

失败后目标路径不会留下本次操作产生的任何不完整文件，也不会改动原先存在的对象。

### 参数与状态码

- `wrapfile --version`：输出版本号，状态码 0。
- `wrapfile keygen <密钥文件路径>`：成功状态码 0，生成失败状态码 1。
- 缺少路径、多给参数、使用未知选项（或任何无法识别的调用）：状态码 2，
  并在标准错误显示用法，不生成任何文件。

```text
Usage: wrapfile --version
       wrapfile keygen <KEY_FILE>
```

### 密钥的保管

密钥文件是**秘密**，应当像密码一样妥善保管（避免放入公开目录、代码仓库、
日志或随备份明文外传）。密钥只存在于这 32 字节中，**一旦遗失，无法凭文件名、
生成时间或任何其他信息恢复其中的密钥**，用它加密的备份也将无法解密。请自行
安排安全、可靠的密钥备份（例如离线副本），并确保副本同样不被他人读取。

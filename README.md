# wrapfile

当前版本提供命令行版本查询与备份密钥生成。

## 构建与运行

```sh
cargo build --offline
./target/debug/wrapfile --version
```

输出：

```text
wrapfile 0.1.0
```

## 生成密钥文件

后续加密备份所需的密钥通过 `keygen` 子命令生成：

```sh
./target/debug/wrapfile keygen path/to/backup.key
```

成功时以状态码 0 结束，并在标准输出简短提示保存位置，例如：

```text
Key saved to path/to/backup.key
```

### 密钥文件格式

- 内容是**恰好 32 字节的原始二进制密钥**。
- 不含任何文本编码（如 hex/base64）、换行、文件头或其他附加字节。
- 密钥字节来自操作系统的密码学安全随机源（由成熟的 Rust 库
  [`getrandom`](https://crates.io/crates/getrandom) 提供，Linux 上为
  `getrandom(2)` / `/dev/urandom`），与时间、路径等无关，不可推算。
- 命令的标准输出与错误信息都不会包含或展示密钥字节。

### 文件权限

在 Unix 系统上，成功生成后留在磁盘上的密钥文件权限**恰为 `0600`（仅当前用户
可读写）**，无论 umask 宽松还是严格都一样：

- **不依赖默认 umask**：umask 宽松（如 `0000`）时，组和其他用户也不会获得任何
  权限；umask 严格（如 `0777`，会连同所有者权限一起屏蔽）时，命令会在写入前
  重新设置并确认权限，`0400`、`0200`、`0000` 都不会被当作成功结果。
- **从创建那一刻起就不暴露**：文件以不含组/其他权限位的模式创建，不会先以宽松
  权限开放、再在结束时收紧。
- **先确认权限，再写入密钥**：在写入任何密钥字节之前，命令会显式将权限设置为
  `0600`（该设置不受 umask 影响），并再次读取文件状态、确认权限位恰好是
  `0600`（所有者可读可写，组和其他用户无任何权限）。
- **无法保证权限则失败**：如果底层文件系统拒绝设置、或无法确认这一权限，命令以
  **状态码 1** 失败，在标准错误说明权限问题，**删除本次生成的文件**，也不输出
  成功提示；已有的其他文件和目录权限不会被改动。

### 拒绝覆盖与路径要求

生成操作只接受一个尚不存在的路径，以下情况都会**失败（状态码 1）**，且已有的
文件、目录或符号链接及其内容保持原样：

- 目标位置已存在任何文件、目录或符号链接（包括指向不存在位置的悬空符号链接；
  命令不会沿符号链接创建文件）；
- 目标的父目录不存在——命令**不会自动创建父目录**；
- 父目录不可写、随机源不可用、写入未完成，或无法将权限设置并确认为 `0600`
  （包括严格 umask 导致所有者权限缺失、文件系统不支持所需权限的情况）。

失败后目标路径不会留下本次操作产生的任何不完整文件，也不会改动原先存在的对象。

### 随机源不可用

32 个密钥字节在目标文件被创建**之前**就向操作系统的密码学安全随机源取齐；
随机源最终返回错误、无法继续取得随机数据时，命令在触碰文件系统之前以
**状态码 1** 结束：

- 标准错误明确说明**密码学安全随机源不可用**，并附上随机源给出的失败原因
  （原因的具体文字随系统/库而变，命令不依赖、回归也不断言随系统变化的完整
  底层错误文本）；标准输出保持为空，不打印保存位置提示。
- 目标位置不会出现空文件、只含部分字节的文件、把已取得字节补零凑成的 32
  字节文件，或任何看似完整的替代密钥；父目录里也不留下本次操作产生的其他文件。
- 已经取得的随机字节立即丢弃：既不会保存，也不会以原始字节或十六进制等文本
  编码的形式出现在标准输出或标准错误中。
- 一次只返回部分数据（短读）或被信号中断（`EINTR`）但仍可继续读取**不算
  失败**：命令会继续读取直到取齐恰好 32 字节，再正常保存为唯一一份密钥。
- 目录中原有的其他文件及其内容、权限，以及父目录权限都保持原样；目标本来
  就是已有文件或符号链接时，该对象及其链接指向都不会被删除、改写或改权限。

### 参数与状态码

- `wrapfile --version`：输出版本号，状态码 0。
- `wrapfile keygen <密钥文件路径>`：成功状态码 0，生成失败状态码 1。
- 缺少路径、多给参数、使用未知选项（或任何无法识别的调用）：状态码 2，
  并在标准错误显示用法，不生成任何文件。

```text
Usage: wrapfile --version
       wrapfile keygen <KEY_FILE>
```

### 密钥的保管

密钥文件是**秘密**，应当像密码一样妥善保管（避免放入公开目录、代码仓库、
日志或随备份明文外传）。密钥只存在于这 32 字节中，**一旦遗失，无法凭文件名、
生成时间或任何其他信息恢复其中的密钥**，用它加密的备份也将无法解密。请自行
安排安全、可靠的密钥备份（例如离线副本），并确保副本同样不被他人读取。

## 权限约定的回归测试

`cargo test` 会对上述文件权限约定做自动化回归保障（Unix，当前工具链为
Linux/glibc；在其他系统上相关用例会自动跳过）：

- 在进程内 umask `0022` / `0000` / `0777` 下分别运行 keygen，断言恰好
  32 字节、最终权限恰为 `0600`、标准输出只有保存位置提示、且 stdout/stderr
  都不含密钥字节。
- 通过 `tests/support/permfail` 提供的 LD_PRELOAD shim，从进程内部记录
  `open`/`fchmod`/`fstat`/`write` 时序，断言文件从创建那一刻起组/其他位即
  全部关闭，并在**任何密钥字节写入之前**已经把权限设为并经 `fstat` 确认为
  `0600`（首次 `write` 前 size 为 0、mode 为 `0600`）。
- 用同一 shim 注入故障：`fchmod` 返回 EPERM、`fstat` 无法完成、以及文件
  系统谎报存储的 mode（`0000`/`0644`）。断言命令返回 1、stderr 说明权限
  问题、无成功提示、未写入任何密钥字节、本次目标被清理，且父目录及兄弟
  文件/inode/内容/权限均不被改动。
- 覆盖已有文件、目录、悬空符号链接（不跟随、不替换）、父目录缺失等既有
  保护规则，以及 `--version` 与参数错误退出码 2 的行为不变。

另有 `tests/keygen_unix_paths.rs` 保障 Unix 下的路径处理规则：生成操作只使用
用户交给命令的原始路径，显示提示时对路径做的（有损）文字替换不决定实际创建
或拒绝创建哪个文件：

- 含非 UTF-8 字节的合法文件名可正常生成（状态码 0、恰好 32 字节、权限
  `0600`、stdout 保留保存位置提示、stderr 为空），且不会因显示转换额外创建
  文件名含 U+FFFD 替代字符的文件。
- 同一目录下两个原始字节不同、显示相同的名字互不混淆：目标是否存在只按原始
  路径判断；显示相同的兄弟文件不被当作目标、不被改写或改权限；原始目标已
  存在时返回 1、保留已有内容与权限，也不会转而在显示后的名字下生成。
- 紧跟 keygen 的 `--` 之后的唯一参数按文件名处理（即使以 `-` 开头或同时含
  非 UTF-8 字节）；没有 `--` 时以 `-` 开头的参数仍是未知选项错误（状态码 2、
  stderr 显示用法、不留新文件）；`--` 不改变只接收一个路径的要求。

`tests/keygen_random_source.rs` 保障**随机源不可用时不会留下可被误认为有效
密钥的文件**（见上文“随机源不可用”）。故障同样通过 permfail shim 注入，
`getrandom(2)` 相关旋钮包括 `WRAPFILE_TEST_RAND_PARTIAL`（每次只返回部分
字节的短读）、`WRAPFILE_TEST_RAND_EINTR`（先返回若干次 `EINTR`）以及
`WRAPFILE_TEST_RAND_FAIL_AFTER=N`（取得 N 个字节后随机源返回不可恢复错误，
`N=0` 即一个字节都未取得）：

- 尚未取得任何随机字节即失败，与已取得部分字节（1/7/12/31 字节等前缀）后、
  补足 32 字节前失败：均断言状态码 1、stderr 明确说明密码学安全随机源不可用
  并给出原因（不断言随系统变化的底层错误全文）、stdout 为空，目标路径不存在
  空文件/部分文件/补零文件或替代密钥，目录内无其他新增文件；已取得字节既不
  落盘，也不会以原始或十六进制形式出现在输出中；trace 还断言随机获取发生在
  创建文件之前。
- 短读与 `EINTR` 被断言为**可继续**：多次读取恰好拼满 32 字节、字节不重复
  不遗漏，落盘内容与读取序列完全一致，正常以状态码 0 保存；shim 已加载但未
  设置任何故障旋钮时，仍使用真实随机源（两次生成的密钥不同）。
- 随机源失败时，目录内已有文件、已有符号链接及其指向对象的内容、inode 与
  权限，以及父目录权限均保持原样；故障解除后重试可正常生成完整密钥。

要让 shim 能拦截随机获取，Linux 上的测试构建通过仓库内 `.cargo/config.toml`
（仅对 `target_os = "linux"` 生效）把 getrandom 切到经 glibc 调用
`getrandom(2)` 的 `linux_getrandom` 后端：该 crate 在 Linux 上的默认
`linux_raw` 后端直接以内联汇编发起系统调用，LD_PRELOAD 无法介入。两者封装的
是同一个内核调用、语义相同，命令行为与密钥文件格式不变；不设置故障旋钮、或
不加载 shim 时随机源完全不受影响，其他平台则继续使用各自的默认后端。

shim 由 `build.rs` 调用系统 `cc` 编译进 `OUT_DIR`，不引入任何新的 Rust
依赖（仍可 `cargo test --offline`）。
